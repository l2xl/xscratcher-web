DataHub

Универсальный асинхронный конвейер данных с хранением в SQLite, планировщиком на базе Boost.Asio и lock-free очередями сообщений.

Исходный код на GitHub → К The Exchange Scratchpad

Архитектура

Диаграмма ниже показывает полный конвейер данных — от сырых байт из сети до уведомлений подписчиков в памяти. Каждый компонент реализует единую концепцию data acceptor и может быть исключён из конвейера, если избыточен. Например, стакан заявок не имеет представления в БД: data adapter передаёт данные напрямую в data feed (data sink опускается).

Обзор

DataHub — header-only библиотека на C++23, реализующая полный асинхронный конвейер данных без накладных расходов в рантайме благодаря статическому полиморфизму и compile-time рефлексии. Она соединяет сетевые источники (WebSocket, HTTP REST) с типизированными коллбэками подписчиков, с опциональным сохранением в SQLite на стадии data sink.

Всё планирование выполняется на общем исполнителе Boost.Asio. Lock-free очередь spsc_queue соединяет поток приёма из сети со strand диспетчеризации, обеспечивая упорядоченную неблокирующую доставку без динамического выделения памяти на горячем пути. Генерация схемы и JSON-сериализация обрабатываются во время компиляции через рефлексию Glaze — без макросов регистрации, без runtime type maps.

Основные компоненты

▶
data_dispatcher<Acceptor...>

Принимает сырые JSON-строки от любого транспорта. Помещает каждое сообщение в lock-free очередь spsc_queue и отправляет задачу на обработку в boost::asio::strand. Strand сериализует обработку — все вызовы адаптеров упорядочены и потокобезопасны. Несколько адаптеров перебираются через C++23 fold expression (A₁ || A₂ || … Aₙ): первый адаптер, вернувший true, поглощает сообщение.

▶
Data Adapter

Десериализует JSON-строку в типизированный C++-структуру с помощью Glaze. Вызывает нижестоящий обработчик и возвращает его результат bool — false означает «не обработано», что позволяет передать сообщение следующему адаптеру в цепочке диспетчера.

▶
Data Sink

Владеет shared_ptr<Model> (обычно data_model). Вызывает model->accept(range) для сохранения входящих сущностей и получения обратно только новых или изменённых.

▶
Data Model

DAO с RAII-созданием таблицы при конструировании. Использует compile-time рефлексию Glaze для получения имени таблицы, типов столбцов и первичного ключа — без ручного написания SQL-схемы. accept() выполняет предкомпилированные выражения INSERT OR REPLACE и возвращает только строки, которые были вставлены или фактически изменены. Поддерживает опциональный table_suffix для шардирования по символу. Полный CRUD, count() и drop_table() включены.

▶
Data Feed

In-memory кэш, обеспечивающий быстрый доступ к актуальным данным для подписчиков.

▶
Data Subscription

Абстрактный интерфейс уведомлений.

Подписчики хранятся как weak_ptr — истёкшие подписчики молча удаляются при следующем уведомлении.
