AI-Asassin

Универсальный AI-ассистент, который сворачивает ваш диалог в граф утверждений и отвечает на каждую реплику из этого графа — а не из стенограммы.

AI-революция начинается — прямо сейчас

В короткой перспективе всё, что можно делать на компьютере, будет делаться через AI или с помощью AI. Разрыв между тем, что AI уже умеет, и тем, что предлагают торговые инструменты, растёт с каждым месяцем.

LLM сметают фигуры с доски. AI позволит людям по-настоящему стать создателями. Мы используем AI для своей работы; мы строим AI, чтобы помочь нашим пользователям стать создателями.

Что делает AI-Asassin

Разговор с AI-Asassin начинается как обычный AI-чат. Шаг за шагом диалог превращается в направленный ациклический граф (DAG) утверждений — Synergy Context Gate (syngate): фраза, выдержавшая обсуждение, становится узлом — коротким утверждением, родители которого — те элементы, из которых оно следует, — и разговор продолжается, привязанный к элементам, а не к хвосту стенограммы. Граф становится движком контекста: реплика, привязанная к элементу, получает ответ ровно из той цепочки рассуждений, которая ведёт к обсуждаемому месту, и того, что его детализирует, — не из всей истории и не из её огрублённого пересказа. Каждый ответ либо продолжает диалог, либо сворачивает его обратно в граф, а последнее слово остаётся за вами: вы проверяете, что граф утверждает.

💬
Диалог → граф: анализ

Элементы — обычные текстовые файлы в вашем репозитории: YAML-заголовок над утверждением в markdown, и единственное, что задаёт форму графа, — их родители. AI-агент перестраивает граф через вызовы дерева — добавить, удалить, переместить — и никогда не правит файлы напрямую, поэтому каждое изменение явно и атрибутируемо.

🎯
Граф → контекст: синтез

Исходный контекст элемента — цепочка утверждений его предков от корня, затем его собственное, затем утверждения всех его потомков — каждый элемент один раз, по порядку. Эта выборка, и только она, формирует ответ на реплику, привязанную к элементу: модель получает не меньше и не больше нужного.

🔒
Гейт: ревью и тесты

Две необязательные дисциплины превращают граф в гейт. Ревью ставит на элемент штамп вашего одобрения — граф не может разойтись с тем, о чём договорились. Тест привязывает элемент к исполняемым процедурам, замороженным по хэшу при одобрении — сначала тест, ещё красный, — граф не может разойтись с тем, что делает код.

💻
Локальный редактор и CLI

Локальный редактор показывает граф как оглавление и как один структурированный документ, с AI-чатом внутри панели каждого элемента; CLI — те же вызовы дерева из терминала. AI-модели подключаются через коннекторы — модель, уровень усилий и режимы вызова выбираются для каждого обмена.

Как на нём строится Open Trader

Определение архитектуры продукта через анализ и синтез диалога — один из сценариев этого цикла. С включёнными тестами и ревью граф программного проекта — это его дерево архитектуры и контрактов: каждое листовое определение привязано к тесту, замороженному при одобрении, а исходный контекст элемента — это контекст, с которого стартует сессия AI-кодинга. Open Trader — именно такой проект: его CI прогоняет гейт на каждый push, — как и сам AI-Asassin.

AI-Asassin опубликован под лицензией IPRL на github.com/l2xl/ai-scratcher. Установка: pipx install git+https://github.com/l2xl/ai-scratcher.git, затем syngate ui внутри управляемого проекта.
