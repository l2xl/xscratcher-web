About the project

An independent open-source initiative. Transparency and self-custody by design.

Where this came from

The Scratcher Project started from a specific frustration: the best tools for trading and managing crypto are either closed-source SaaS products you cannot fully trust, or raw APIs that require writing custom integration code from scratch every time. Neither option is acceptable for infrastructure that handles real money.

The goal here is to build the open-source middle ground — proper applications, not scripts. Software with real interfaces, verifiable behaviour, and source code anyone can read and audit.

What "The Scratcher Project" means

Scratching the surface usually signals that you have barely started — that the real work is still ahead. We treat that as an advantage. The most durable software gets built by teams that stay genuinely curious, keep questioning first assumptions, and resist locking in to the earliest solution that works.

This project is built incrementally and in the open. Shipping early, gathering real feedback, and rethinking what is not working are features of the process, not failures.

Open source, without exceptions

Every project here is fully open source — not "open core" where the useful features require a paid plan, and not "source available" under a license that prohibits commercial use. Actually open: MIT or equivalent, forkable, auditable, and buildable by anyone.

For crypto tooling specifically, this is not a philosophical preference — it is a basic security requirement. Software that handles private keys or executes trades on your behalf must be inspectable. Open source is the only way to verify what is actually happening.

Zero Trust by design

We build our products so that even we cannot act on a user's behalf without their explicit action. Exchange API keys stay on the user's device. Strategy execution is scoped to the minimum permissions required. Every algorithm is in the open codebase.

This is not a marketing claim — it is an architectural constraint we apply from the start of each project, not a property we add later.

The intellectual property question

Building in the open does not mean giving up the ability to sustain the work long term. The IP Reserve License is our approach to this problem: keep code open during the pre-incorporation phase while preserving the intellectual property as a documented foundation for whatever structure comes next. We use it ourselves and share it freely with anyone in the same position.
